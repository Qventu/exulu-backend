Release · Connect Your Agent

Your skills library, in every coding agent.

One command connects Claude Code, OpenCode and 48+ other coding agents to your Exulu skills library. From then on your agent can list, install, update and publish skills itself — no browser round-trips, no copy-pasting skill files.

One line to connect

The skills library hands you the command — your terminal does the rest.

The Skills page has a new "Connect your agent" button. It opens a dialog with a single copy-ready command, pre-filled with your instance's address — run it in any terminal and your coding agent is wired to this Exulu instance. The dialog says exactly what will happen next: your agent asks which clients to install into, and whether to share one copy across them via symlinks.

You'll need an API key — create one in Settings. The key is stored locally with owner-only file permissions and is never passed on the command line.

bash — the one-liner, with your instance's URL baked in
curl -fsSL https://exulu.your-company.com/api/skills/install.sh | sh

An installer that knows your agents

Pick your clients once — existing ones come pre-selected.

The script resolves your backend, asks for your API key, and then shows a multi-select of coding agents to install into — clients it finds on your machine are already ticked, and the cross-agent .agents/skills/ standard is the default. Choose copies for maximum compatibility, or symlink mode to share one copy across every client with a single place to update.

Ask your agent what's in the library

"List exulu skills" — straight from the chat.

Once connected, the exulu-skills skill teaches your agent the library. Ask it to list skills and it returns every skill you can access on your instance — name, description, tags and current version — governed by the same access rules as the platform UI: you only see what you're allowed to see.

The helper your agent calls under the hood
exulu list                      # skills you can access
exulu get <name>                # one skill's metadata
exulu install <name>            # install into your agent clients
exulu update [<name>]           # update all installed skills, or one
exulu publish <name> <dir>      # publish a local skill folder
exulu config                    # show backend / scope / clients

Install a skill without leaving the chat

"install grill-me" — and it's in every client you connected.

Tell your agent to install a skill and it lands in all your connected client directories in one step — as copies, or as symlinks to a single shared source if you chose symlink mode. Each installed skill carries a marker file recording its name, version and source instance, so update later knows exactly what to refresh.

Publish your own skills back

A skill folder on your machine becomes a versioned library entry.

Built a skill locally? Ask your agent to publish it. The folder is zipped and pushed to the library — a new name creates version 1, publishing an existing name you own bumps the version. Your whole team can install it seconds later, from their own agents.

REST — the registry behind it (same API the helper uses)
# list skills you can access
curl -H "x-api-key: Bearer $EXULU_API_KEY" \
  "$EXULU_BACKEND/skills/registry"

# download one (latest or a pinned version)
curl -H "x-api-key: Bearer $EXULU_API_KEY" \
  "$EXULU_BACKEND/skills/registry/grill-me/download?version=latest"

# publish a new version (zip body)
curl -X POST -H "x-api-key: Bearer $EXULU_API_KEY" \
  --data-binary @grill-me.zip \
  "$EXULU_BACKEND/skills/registry/grill-me"
