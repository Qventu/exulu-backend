Platform Release · 22 June 2026

Knowledge, connected.
Cost, controlled.

Five shipped upgrades that make Exulu's retrieval sharper and its spend predictable. Meetings become searchable transcripts, an entity graph deepens retrieval, and the knowledge pipeline shows its work end to end — while you get live, per-tag control over what it all costs.

01 — Meetings

Send a bot to any meeting

Drop in a meeting link — Exulu joins, records, and transcribes, then runs your prompts on the result automatically.

Paste a Zoom, Meet, or Teams link and Exulu sends a bot to join, record, and transcribe the call. When it's done, the recording comes back as a speaker-labeled transcript you can review and rename — and any prompts or agents you attached (a summary, an action-item extractor, a notetaker) have already run against it.

Meetings become searchable knowledge without anyone taking notes, flowing straight into the same pipeline as the rest of your documents.

GraphQL
mutation MeetingBotStart($input: MeetingBotStartInput!) {
  meetingBotStart(input: $input) { ...TranscriptionJobFields }
}
02 — Knowledge

A pipeline that shows its work

Watch every document move Ingested → Processed → Embedded → Ready to search — live, with the next action right there.

Every knowledge item now carries a live pipeline stepper, so you can see exactly where a document is and kick off the next stage with one click instead of guessing. No more black-box ingestion.

A pipeline-health view rolls the whole base up into a single "is this searchable?" number and surfaces anything stuck — before it quietly breaks retrieval. Durable per-item job tracking means the status survives a refresh.

03 — Cost

Cap spend on anything

Set a budget per user, team, project, or agent — and watch the burn rate, with a projection that flags overspend before it happens.

Spend is now governed by tags. Put a cap on any user, team, project, or agent and Exulu meters every model call against it through the LiteLLM proxy. Animated burn-down bars and a dashed projection marker flag who's on track to blow their budget before the bill arrives.

A chip in the top bar keeps each person's own spend in view, and the analytics page breaks it all down by tag and by day.

REST
PUT  /admin/budgets/:entityType/:entityId   # upsert one budget
PUT  /admin/budgets/:entityType/bulk        # apply to many entityIds[]
GET  /me/budget                             # caller's own spend (in-chat)

# entityType ∈ user | role | team | project | agent
04 — Retrieval

A connected entity graph

Turn documents into People, Companies, and Products — sharper retrieval, and a graph your agents can follow.

Switch on entity extraction for a knowledge base and Exulu reads the entity types you define out of every document. Those shared entities sharpen retrieval — a soft re-rank that disambiguates and boosts on top of hybrid search — and give agents a graph to follow between related records.

A one-click backfill brings your entire existing corpus into the graph, and suggested types surface entities worth promoting.

From the SDK
new ExuluContext({
  id: "contracts",
  entities: {                       // declaring this turns the layer on
    types: [
      { name: "Person",  description: "Individuals named in the contract" },
      { name: "Company", description: "Legal entities / organizations" },
    ],
    model: "<models.id uuid>", boostWeight: 0.3, canonicalLanguage: "english",
  },
});
05 — Models

One path for every model

Reranking, embeddings, and OCR now route through the LiteLLM proxy — swap any provider in YAML, and every call is cost-attributed.

Reranking, embeddings, and OCR now run through the same proxy as your chat models. You can swap providers by editing one YAML file — pick any reranker, embedder, or OCR model in the catalog — and every call is automatically tagged and cost-attributed alongside everything else. One control plane for every model Exulu touches.

config.litellm.yaml
- model_name: rerank-v4.0-pro
  litellm_params:
    model: cohere/rerank-v4.0-pro
    api_key: os.environ/COHERE_API_KEY
  model_info:
    type: reranker        # ← makes it a selectable reranker
    top_n: 20
