See what the agent does. Decide what it may.

Enterprise-grade control lives right inside the conversation: approve sensitive tool calls before they run, verify every answer down to the source PDF page, and steer the agent through structured question cards and visible plans.

Tool-call approval

Nothing runs without your say-so.

When an agent wants to run a sensitive tool, the stream pauses and an approval card renders right in the conversation, inside the assistant turn: a quiet shield icon, the title "Run Email?", one explaining sentence, and a monospace preview of the actual tool input — no dead chevron rows, everything readable up front. Three actions with a clear hierarchy: Allow once (primary purple), Allow for this chat, and Deny (destructive). Click Allow once and the card collapses to a quiet green "Approved: Email" row, and the agent picks the stream right back up.

Allow for this chat approves the pending call and persists the tool under this one conversation, sent with every subsequent request so the card never re-appears for that tool in this session. Those pre-approvals are no longer invisible or irrevocable: the capability sheet grows an "Approved for this chat" section — "Tools allowed to run without asking again in this conversation." — listing each pre-approved tool with a green status dot and a per-row "Revoke" button. Denying is honest too: the card collapses to a red "Denied: Email" row, the agent is told the call was refused, and it answers with what it can do instead.

Approval-by-default is a backend contract, not a frontend nicety: every custom tool asks first. The built-in sandbox readFile / writeFile / bash run approval-free — they operate inside the session sandbox — so the cards appear exactly where the stakes are: email, integrations, external actions.

Citations

Every answer shows its work — down to the page.

Answers cite their sources, and the sources defend themselves. When retrieval backs a claim, the renderer turns the model's citation into a compact badge right where the claim is made ("Reports - Quarterly Report.pdf #4"). Clicking the badge opens a provenance dialog that fetches the chunk live: the exact retrieved chunk text, a Field/Value metadata table (Source, Chunk #, Item ID, Item External ID, Created at, Updated at), and — when the chunk came from a PDF — the source PDF embedded and opened at the cited page. The preview resolves asynchronously and swaps in over the chunk-text zone, so the eye connects chunk to page in a single click.

The same dialog carries a destructive "Deactivate this source" action, with the consequences stated up front — "Deactivating archives this item globally — it will no longer appear in any user's chat or search results." Confirm it and the item is archived globally behind a "Deactivate this source?" dialog, then a "Source deactivated" toast — so a bad source gets pulled from exactly where you found it, no hunting through the knowledge base.

Internet-search claims get the sibling treatment: a favicon + title + hostname badge ({title} · {hostname}) opening a dialog with the quoted snippet in a purple-edged blockquote, the live page embedded, and a Domain/Page table. Citations stay attached to the exact sentence they support — the renderer rewrites the model's inline blobs into badges during markdown rendering, even mid-stream.

Question cards

Agents that ask before they act.

When the agent needs a decision, it renders an interactive card inside the transcript: a header with the question, a stack of checkbox options with true multi-select, and a full-width purple "Confirm selection" button — disabled until at least one option is ticked. Confirming sends the chosen options back into the conversation as check-marked purple pills in a normal user bubble, so the decision survives a page refresh and stays part of the conversation the agent can see. The card protects itself: "Confirm selection" stays disabled with nothing ticked, and the whole card disables while the agent is streaming — no double-answers, no dead clicks.

The agent's plan shows the same way. A todo list renders as a compact checklist that updates in place — a green check with strikethrough for completed steps, a blue spinner on the item in progress, a muted circle for pending — with a thin purple progress bar counting n/m. High-priority items get a red "(!)" marker. Only the agent's latest task list is kept, so you watch one live surface change state as the work moves forward.

The answer is just a message — model-agnostic, no special protocol. Both surfaces are built-in agent tools you toggle per-agent exactly like any other tool.

Decide what the agent may use, per conversation

Every skill and tool the agent carries, switched on or off — for this chat.

The "Skills & tools" sheet — opened from the ＋ menu in the composer — lists every skill and tool the agent carries, each with its own switch, plus per-section "Enable all" / "Disable all". Anything you approved mid-conversation shows up under "Approved for this chat" — "Tools allowed to run without asking again in this conversation." — with a per-row "Revoke" button, so a one-time "Allow for this chat" is never an invisible, permanent grant.

When capabilities are switched off, a quiet "N off" badge sits on the ＋ trigger itself, so a non-default setup is visible before you send the next message. The count only reflects this agent's own capabilities, so a stale toggle can never inflate it.

Share a conversation without giving away the pen

Hand out the link, keep control of who can write.

"Share conversation" hands out the link — "Anyone with access can open this conversation at the link below." — and an "Access" collapsible holds the actual rights editor: private, shared with specific users, or shared with roles, each recipient set to Read or Write, saved with "Save access rights".

Recipients without write access get the full transcript but not the pen: the composer is replaced by a muted lock bar — "Read-only — shared by {email}. Ask them for write access." — naming the owner instead of leaving a dead input. Write access stays with the creator, listed users and roles marked write, and super admins; everyone else reads along.

Find any conversation, delete fifty at once

A debounced title search and bulk delete, per agent.

Every agent now has a "Search conversations" page: type three characters or more into "Search by title…" and a debounced server-side title search narrows the list, each row a title plus relative timestamp, with "Show more (N of M)" paging in 50 at a time.

Flip on "Select" and checkboxes appear on the rows you're allowed to touch — select-all included — ending in one destructive "Delete N chats" action behind a confirm that spells out the stakes: "This permanently deletes the N selected conversations for everyone with access. This can't be undone."

See how the answer was built

A numbered reasoning timeline you can unfold and audit.

While an agent works, its reasoning renders as a numbered timeline — each step a small numbered bubble with the agent's thinking and chips for every tool it called; click a chip and it unfolds into the actual Input and Output of that call.

Long runs stay readable: streaming shows only the latest five steps (older ones wait behind "N more reasoning steps - show all"), and once the answer lands the whole trail collapses to a single quiet line — "N reasoning steps - show details" — expandable whenever you want to audit the run.

Thumbs-down that fixes the source, not just the answer

Pull a bad source for the whole team from inside the feedback dialog.

A thumbs-down now opens "What could be improved?" — and beneath the free-text field, "Sources referenced in this response" lists every knowledge item the answer actually cited. Knowledge curators get a per-source "Deactivate" button with the consequences stated up front — "Deactivating archives the item globally — it will no longer appear in any user's chat or search results."

A two-step inline confirm ("Archives "{item}" globally for every user." → "Confirm deactivate") keeps it all in one place, so one bad source can be pulled for the whole team from inside the feedback dialog — no modal-on-modal, no hunting through the knowledge base.
