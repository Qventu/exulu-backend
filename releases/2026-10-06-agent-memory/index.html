Agent memory, end to end

Memory stopped being a hidden system-prompt injection and became something you can see, correct, measure and argue with. Five parts shipped together: the save card in chat, the Memory area, usage tracking, conflict detection, and a map of the whole base.

Memory, in the open

Your agent remembers — and you approve the words.

Memory already worked. It was just invisible: a question in chat, a generic approval, a system-prompt injection nobody saw.

Now the agent has three tools — remember, update and forget — and the consent step is the save card. You approve the exact sentence that gets stored, and you can edit it before you do. Nothing reaches the base that you did not see.

The Memory area

One place that answers: what has this agent actually learned?

Under Build there is now a Memory area: every base, every agent, and one memory in full.

It is built over the knowledge workspace you already know, so filters, access control and the item dialogs behave exactly as they do everywhere else. A base page opens on a stats strip — how many memories, how many used this month, how many never used, how many in conflict.

What the agent actually uses

Half a base is never read. Now you can tell which half.

Every memory recalled into an answer is recorded — one record per recalled memory per answer, guest conversations included. Nothing about the content, only the fact of the use.

That gives a Last used column, a usage filter for never-used and stale memories, and a bulk Archive for the leftovers. Archived memories leave recall and the counts and can be restored from Knowledge — they are not deleted.

Conflicts

Two memories disagree. The agent believes both.

A base accumulates near-duplicates and outright contradictions, and until now nothing surfaced them.

A scan per base finds both: duplicates by similarity, contradictions judged by a structured model call per candidate pair. Three resolutions — keep one, merge into a single memory, or dismiss as not a conflict — and the decision is stored. Only shared memories are scanned; private memories never enter detection.

Run a scan from the API
mutation MemoryConflictsScan($contextId: ID!) {
  memoryConflictsScan(contextId: $contextId) {
    open
    duplicateGroups
    contradictionGroups
    judged
    scannedAt
  }
}

The map

A list tells you what is in a base one row at a time. The map tells you what it is about.

Every passage carries a position computed from its embedding, so a base draws as a cloud where near means similar — and it works on knowledge bases as well as memory.

Regions are clusters, named from the distinctive words in the text index that search already keeps. No model is asked, so a region's name is the base's own vocabulary. Select a dot and the map draws lines to the passages worded most like it and opens the item beside the cloud. On a memory base, a slider filters by when a memory was added, so you can watch the base fill in.

Only passages you may read are drawn, and the caption says how many of how many are on screen.

The map's read API
query ContextMapPoints($contextId: ID!) {
  contextMapPoints(contextId: $contextId, mode: PASSAGES, limit: 5000) {
    points { id itemId x y z itemName group chunks createdAtMs }
    total
    sampled
  }
}
