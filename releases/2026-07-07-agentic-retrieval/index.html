Agentic Retrieval, rebuilt around you.

The retrieval engine behind knowledge search is now a deterministic four-phase pipeline — understand, search, rerank, verify against memory — and every part of it is configurable from a guided, plain-language wizard in the agent editor. No JSON, no guesswork: say what your sources hold, how your users talk, and how thorough you want answers to be.

A guided setup, not a settings dump

A summary card shows the whole configuration at a glance; a six-step wizard edits it in plain language.

The Agentic retrieval card in the agent editor now carries a one-line digest of the whole setup — "4 knowledge bases · 3 routing rules · memory on · reranker: …" — with buttons that jump straight into the relevant step of the new configuration wizard: Sources → Routing → Vocabulary → Memory → Behavior → Review. It opens automatically the first time you enable the tool.

Every control in the wizard comes with a one-sentence explanation and a concrete example, so the person configuring retrieval doesn't need to know what "RRF fusion" or "HyDE" is — they just answer questions about their content. Under the hood, each query runs a deterministic pipeline of small LLM calls that classify the question, detect document references, search the right sources in parallel, rerank, and check curated memory. And it degrades gracefully: if any single step fails, the pipeline skips that feature and still retrieves.

Sources — say what each knowledge base holds

Each knowledge base gets a content profile, and the pipeline searches it the way that content wants to be searched.

For every knowledge base you enable, you answer one question — "What's in it?" — and the pipeline adapts its whole search strategy:

  • Documents & manuals — searched thoroughly with query expansion: multiple query variants are fused together, and matching passages bring up to seven neighboring sections with them. Best for manuals, PDFs, and long documents (up to 100 passages).
  • Conversations & tickets — matched by names and keywords first, then searched. Best for support tickets and email threads, where titles and participants matter more than prose (up to 20 passages).
  • Structured records — searched directly by keywords. Best for database rows and short entries (up to 20 passages).

An optional "When should the assistant look here?" note per source feeds the router, and per-source overrides (passage limits, neighbor expansion, query expansion on/off) are there when you need them. The win: no more one-size-fits-all search that reads a support ticket like a PDF manual.

Routing — the right sources first

Describe kinds of questions in plain language and point them at primary and backup sources.

A routing rule is just a label, a plain-language description ("Questions about products, error codes, installation or specifications."), a set of sources to search first, and a set to also check when the first search looks weak. The pipeline classifies each incoming question against your descriptions and searches accordingly — main sources immediately, backup sources speculatively in parallel, merged only if the main results actually score poorly.

No rules configured? Every enabled knowledge base is searched for every question — a fine default. Rules are how you buy speed and focus: fewer irrelevant sources searched per question, less noise handed to the assistant, and a safety net when the primary sources come up empty. Explicit user requests ("check the regulations") always win over classification.

Vocabulary — teach it your domain language

Users don't phrase questions the way documents are written. This step closes that gap.

Four tools, all optional, all compounding:

  • Glossary — abbreviations and terms your documents use (FST → field bus controller). Glossary terms expand queries so a user's shorthand still finds the formally-worded manual.
  • Names & codes — identifier sets that map mentions to specific files. Product names match approximately (FST, ECO, CBM-2); standards and error codes match exactly (DIN 8100, EN 81-20). When a user mentions one, the matching files are pinned into the search and boosted in ranking.
  • Describe your documents — a free-text description of how your corpus is written (language, structure, conventions). It shapes the hypothetical-answer queries the pipeline generates, so expanded searches sound like your documents.
  • Query rewrites (advanced) — systematic find→replace on the user's question, for wording differences too mechanical to leave to the model.

Memory — curated knowledge that participates in retrieval

Four toggles control how the agent's curated memory entries shape answers.

Use memory during retrieval

Relevant memory entries are retrieved and offered to the assistant alongside document results — as citable results.

Let verified memory override documents

When a curated entry directly answers the question, the answer leads with it — even over the documents. Strictly gated: it requires high confidence and authoritative entries, so a stray note can't hijack an answer.

Follow file hints in memory

Memory notes like "always check X first" pin those files into the search.

Expand queries with memory & glossary

Adds synonyms and expansions from memory and your glossary to the search.

This is how correction feedback loops work: when a document is outdated or an answer needs a caveat, a curated memory entry fixes it — without re-ingesting the corpus. If the agent has no memory knowledge base, the wizard explains that and points to the memory picker instead of showing dead toggles.

Behavior — production-grade tuning without code

The dials that decide answer quality, speed, and cost — each explained in a sentence.

The essentials sit up front: the reranker (re-scores results for relevance; strongly recommended, but the pipeline works without one), results to hand the assistant (top-K — more means broader context, slower and costlier answers), and the backup-source trigger — a slider that decides how readily backup sources kick in when the first search looks weak.

Behind an Advanced collapsible: score boosts for pinned files and identifier matches, the page window for "page 12"-style references, max query variations per source, a utility model to run the pipeline's internal micro-calls on a cheaper model than the agent's own, access gates (managed context, require chosen knowledge bases), debug logging, and a cap on agent steps per message.
