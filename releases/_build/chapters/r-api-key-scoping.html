API-key agent scoping (enterprise)

Mint a key that can talk to one agent — and nothing else.

Any key you ship client-side leaks eventually — and until now a leaked key could reach every agent and every mutation on the platform. API keys now declare a scope mode: admin keeps today's broad behavior (every existing key migrates unchanged), while agents carries a whitelist of agent IDs and can call only the run route for those agents — no mutations, no other agents, no admin surface. Usage and budget caps still apply, so scoped keys inherit their spend limits automatically.

GraphQL — minting a scoped key
mutation CreateUser(
  $type: String, $apikey: String,
  $scope_mode: String, $agent_ids: JSON
) {
  usersCreateOne(input: {
    type: $type, apikey: $apikey,
    scope_mode: $scope_mode,  # "admin" | "agents"
    agent_ids: $agent_ids     # whitelist when scope_mode = "agents"
  }) {
    item { id }
  }
}
