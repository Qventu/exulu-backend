Release · Libraries

Prompts and skills, versioned and shared.

Two shared libraries turn one-off prompt craft and agent skills into governed company assets: searchable, templated, RBAC-shared, and under full version control with visual diffs and rollback.

Skill editor mini-IDE

Build agent skills like a code project — files, versions and Cmd+S, right in the browser.

/skills/[skillId] is now a full-bleed mini-IDE, not a form page. A collapsible file sidebar carries a real tree — create file or folder, rename, delete — and the editor pane opens .md files in a markdown editor while every other extension (scripts, JSON, configs) opens in a plain monospace textarea. Skills are code, and the editor treats them that way.

The header shows the mono file path, an "Unsaved" badge while dirty, and a Save button that stays disabled until you actually change something. Cmd/Ctrl+S saves — a real window-level binding that no-ops when the file is clean or read-only — and a "File saved" toast confirms it. Full file management is one right-click or kebab away; folder deletes warn that "The folder and all its contents will be removed from the current version. This cannot be undone."

Guard rails keep the work safe. Switching files with unsaved edits raises "Discard unsaved changes?" and leaving the route is intercepted by the shared unsaved-changes guard. "Save version" (the top bar's purple button) snapshots the current state into a new slot, and the History sheet opens a file-level diff. Without write access the whole surface degrades gracefully to a "Read-only" badge: every file stays browsable, but Save and the file operations disappear.

Cmd+S is a plain REST flow — script the same save from anywhere
POST /skills/{skillId}/sign
{ "filePath": "SKILL.md", "contentType": "text/markdown" }

# → { "key": "skills/{skillId}/v2/SKILL.md",
#     "url": "<presigned PUT URL>", "method": "PUT" }

PUT <presigned PUT URL>
Content-Type: text/markdown

<new SKILL.md content>

Variable-fill for templated prompts

One prompt library for the whole org — templates carry the blanks; anyone fills them in seconds.

Prompts in the library can carry {{variable}} placeholders — double-braced, letters, numbers, and underscores only. Clicking "Use prompt" on a templated prompt no longer copies the raw template; it opens a variable-fill dialog with one labeled field per detected variable (unique names, alphabetically sorted; report_name becomes "Report Name"). The "Copy to clipboard" submit stays disabled until every field has non-whitespace input — no half-filled templates on the clipboard.

On submit, every {{key}} is swapped for the typed value, the filled text lands on the clipboard, and "Prompt copied to clipboard." fires. Every "Use prompt" now counts: the copy path increments usage_count — previously only chat insertion did — so "Used N times" and the "Most used" sort finally reflect real usage. Prompts without variables skip the dialog: straight copy, toast, and count.

The editor hints the syntax live: "Use {syntax} for dynamic content. Variable names can contain letters, numbers, and underscores.", a "Detected variables:" chip row while typing, and an "Invalid variable names: {names}. Use letters, numbers, and underscores only." error on save. The same fill flow lives in the chat composer's prompt selector — pick a templated prompt in chat and you get the identical fields inline, inserting the filled text into the message box. And in the document view, variables render as safe secondary chips, retiring the legacy regex-highlighted markup that was a stored-XSS surface for shared prompts.

Prompt version history

Every prompt keeps its history — see exactly what changed, roll back anytime.

Every prompt now ends in a "Version history" section: a current-version badge, a version count, and rows newest-first, each showing a mono vN badge, a "Latest" badge on the newest snapshot, the edit's change message as the title line (fallback "Untitled change"), the author, and a relative timestamp. Beyond three versions, the rest collapse behind "Show all".

Each row's "Compare" action opens the "Compare versions" modal — "View the differences between prompt versions." — with a side-by-side red/green content diff and word-level highlights. Both sides are pickable: any version against any other, including the live "Current" state. When name, description or tags differ, a "Metadata changes" summary lists them above the content diff; identical content shows "No content changes between these versions."

Each row's "Restore" action — write-gated, so it doesn't render without write access — opens a confirmation that snapshots your current state into history first ("Current version will be preserved"), previews exactly what will roll back, and takes an optional "Restoration note (optional)" before rolling name, description, content and tags back; the success toast reads "Version restored". History stays clean by design: consecutive edits by the same author within five minutes squash into one entry, and the timeline keeps the most recent 50 versions.

Skill versioning with per-file diffs

Skills, under version control — know exactly what changed, file by file.

Skills are versioned file bundles with real change management. The editor top bar's one purple "Save version" button opens a label dialog — "Snapshot the current state into a new version slot. You keep editing the next version." — then copies every file of the current version into the next slot and appends it to the skill's history. The version history sheet lists snapshots newest-first, the current version pinned on top with a "Current" tag; its empty state reads "No previous versions yet" / "Save a version to snapshot the current state."

The "Compare versions" modal — "View file-level differences between two skill versions." — pairs From/To version selects with a per-file list. Added, removed and modified files carry status icons; clicking a modified file reveals a split red/green diff with word-level highlights, while removed files show as an all-red unified view. Unchanged files are filtered out server-side, so the list is only what actually moved between the two versions.

Any version's full bundle downloads as a .zip with folder structure preserved plus a version.txt — take a skill into Claude Code or any other tool. Below the md breakpoint the compare modal becomes a full-screen takeover, the file list a horizontal chip strip, and diffs render unified instead of split.

Snapshots and diffs are plain REST — script them
POST /skills/:skillId/version
{ "label": "Tightened safety prompt" }
# → { "newVersion": 4, "fileCount": 12 }

GET /skills/:skillId/diff?fromVersion=3&toVersion=4
# → { "fromVersion": 3, "toVersion": 4,
#     "files": [ { "path": "reference.md",
#                  "status": "modified", "diff": "..." } ] }

Find any prompt in three keystrokes

The whole prompt library on one screen — search, sort, filter, and the document always open.

The new /prompts page is a split view: a slim, paginated list on the left and the full prompt document always open on the right. Search is server-side and debounced at 300 ms (placeholder "Search prompts…", by name), and sorting is five-way — "Recently updated", "Recently created", "Most favorited", "Most used", "Alphabetical".

A "Filters" popover stacks a "Favorites only" switch with tag and agent pickers, each active filter landing as a removable chip above the list, and "Reset" clears them all. Fifty prompts per page with a live footer — "1–50 of 132" — and two single-key shortcuts: "/" jumps to search, and "N" opens a new prompt for users with write access.

Every prompt is one click to use and one link to share

Use it, star it, send the link — every prompt has a full shareable page.

The detail pane leads with a "Use prompt" button that copies the content to the clipboard — "Prompt copied to clipboard." — and, fixing a long-standing gap, now actually increments the prompt's usage_count, so "Used # times" and the "Most used" sort finally mean something. A star toggle adds the prompt to your favorites ("Added to favorites.").

The overflow menu carries "Copy content", "Copy link", and Delete; "Copy link" puts …/prompts/<id> on the clipboard ("Link copied to clipboard."), because every prompt now has a full shareable page at /prompts/[id] — with a "Back to prompts" link, working Edit, and a post-delete redirect. The meta line reads out the whole picture: "Created by {name}", a relative time, an access badge, "Used {#} times", and "{#} favorites".

Write once, template forever

One modal for content, variables, and access — content, sharing, and change notes in a single pass.

The editor modal is sectioned into "Essentials", "Organize", and "Sharing & access". A toggle flips the content field between "Plain text" and "Rich text" (a live-preview markdown editor), while {{variable}} tokens are detected as you type and listed under "Detected variables:". Tags are capped at five ("Up to 5 tags. Use them as folders (e.g. \"marketing\", \"support\")."), prompts can be assigned to agents ("Assigned prompts appear as recommendations in chat."), and RBAC sharing covers private, specific users, roles, teams, or public.

On edit, a change-notes field — "What changed? (optional)" with the hint "A short note helps teammates understand what changed in this version." — feeds the version history. History building is pure and predictable: an entry is appended only when content, name, description, or tags actually changed; consecutive edits by the same user within five minutes are squashed into one; and the timeline is capped at the last 50 versions.

Browse skills like files, not like folklore

A library, not a maze — the same split view, with the skill you're inspecting docked open.

/skills gets the same split-view treatment: debounced (300 ms) server-side search ("Search skills"), a "Filters" popover of tags with removable chips, and a docked detail panel so the skill you're inspecting stays open while you scan the list. Multiple tags AND together — a skill must carry every selected tag.

Pagination shows "1–50 of 132" at 50 per page, a count label sits in the toolbar, and "N" opens the create dialog from anywhere on the page. Below the lg breakpoint the detail lifts from a docked panel into a sheet; with nothing selected it reads "Select a skill to preview". The page header sets the frame: "Skills" — "Reusable skill packages your agents can load."

Know what a skill does before an agent loads it

Read it before you run it — the real SKILL.md, versions, access, and a portable .zip export.

Select a skill and the panel shows the actual SKILL.md, clamped to the first 15 lines with a "Show {count} more lines" expander — and a warning when it's absent: "SKILL.md not found" / "Open the editor to create SKILL.md and document this skill." Below it sit inline-editable tags, a compact version history (current version pinned, last three prior versions, "View all & compare" deep-linking into the editor), access control, and a stats footer of "Versions" and "Uses" — with a tooltip that defines the metric: "How many times this skill has been loaded by an agent." The header overflow menu adds "Download as .zip" and "Copy skill ID".

The download is a real REST surface, not a UI-only affordance — any authenticated client can export a skill version as a zip with the folder structure preserved plus a version.txt manifest. Omit the version from the query string and it defaults to the skill's current version server-side.

REST — export any skill version as a portable .zip
# Export any skill version as a portable .zip:
curl -H "Authorization: Bearer $JWT" \
  "$EXULU_BACKEND/skills/$SKILL_ID/download?version=3" \
  --output data-analysis-v3.zip
# → folder structure preserved + version.txt
#   (Skill / Skill id / Version / Files / Exported at)

From zero to editable skill in one dialog

Start blank or bring a bundle — a skill is shareable the moment it exists.

The "New skill" dialog offers two tabs: "Create blank" and "Create from upload". Blank creates the record and seeds a templated SKILL.md before dropping you straight into the editor ("Create & open"); upload takes a drag-and-drop bundle — the ".zip (full skill folder) or single .md file" introduced in the May release — stages it to S3 via a presigned URL, and extracts it into version 1. A wrong file type is caught with "Only .zip and .md files are supported".

Name, description, comma-separated tags, and RBAC access are all set in the same dialog, so a skill is shareable the moment it exists. What's new here is the redesigned dialog itself — tabs, a proper dropzone, and real RBAC control replacing the mislabeled select that used to silently drop the access payload.
