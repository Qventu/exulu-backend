Release · July 8, 2026

The chat got faster, clearer, tidier.

A quality-of-life roundup for the surface you use most. The composer is faster to drive — every tool, skill, and session file is one keystroke away. Answers are more transparent about what they did and what it cost. And context presets and saved transcriptions finally got the housekeeping tools they were missing.

Type / — every tool, one keystroke away

The composer now autocompletes your agent's tools and skills inline — no toolbar hunting, no leaving the keyboard.

Type / at the start of a word and a menu pops up over the composer with everything this agent can actually do — its tools and its skills, each with a one-line description. Keep typing to filter, hit Enter, and the real tool name lands in your message as plain text with a subtle purple highlight: "Check the rollout doc /internet_search". The agent reads the intent straight from your words — mid-sentence, exactly where you meant it.

There's a second flavor for files: on agents with a file sandbox, typing @ lists the files in this session, so you can point the agent at an uploaded report without breaking your sentence to find the attachment panel.

It's deliberately just text — no hidden commands, no side effects. Edit a highlighted token and it gracefully stops being one; fractions like 3/4 and email addresses never trigger the menu; and tools that are currently switched off stay visible (greyed, with a small "off" badge) so you can still reference them.

Context presets, full lifecycle

Apply a preset, tweak it live, save it back — without leaving the chat.

Applying a preset now keeps its identity: a purple bookmark chip with the preset's name leads the pinned-context row, and applying replaces the pinned set cleanly instead of piling on top of what was there. Pin an extra source or drop one mid-conversation and the chip notices — an italic modified tag appears, along with an Update preset button that saves your current set back to the preset in one click.

The preset browser grew the other half of the lifecycle: every preset you can write to now has edit (name, description, tags, sharing) and delete. Deleting uses a two-step inline confirm right on the row — "This cannot be undone." with Cancel beside it — never a second dialog stacked on top of the modal.

Everything is permission-gated the way you'd expect: admins, the preset's creator, and anyone with write access via RBAC. And the chip is per-chat — deselecting it clears your pinned items for this conversation without touching the preset itself.

A thumbs-up teaches your agent

Rate an answer and the retrieval approach behind it gets remembered — and reused on similar questions.

The thumbs on assistant messages now close a learning loop. A thumbs-up marks the retrieval approach behind that answer as proven, making it eligible for instant replay when a similar question comes in — no extra latency, no model call. A thumbs-down with a comment goes further: it's routed to a feedback agent that prunes or rewrites the strategy so the same miss doesn't repeat.

When an answer did reuse a proven approach, it says so — a quiet badge reads "Answered like a similar earlier request." No jargon, and the tooltip nudges you toward the fix if it got it wrong: give it a thumbs-down below.

Your feedback also lands on the right target, even deep into a conversation: the rating walks back through the history, and on a replayed answer it credits (or corrects) the original proven approach rather than the copy. Positive ratings are a safe fast-path by design — they can never delete or rewrite anything.

Every answer shows its receipt

Retrieval cost and per-message token split, inline — nothing to configure, nothing new to learn.

Under every knowledge-search result

↳ retrieval · 2,412 in / 486 out tokens · 3.2 s

In every message footer

1,412 tokens · 1,120 in / 292 out

Retrieval used to be a black box: you saw the sources, not the cost. Now every knowledge search prints its receipt right under the result — input and output tokens plus wall-clock time — so a heavy query is visible the moment it happens, not at the end of the month in an analytics view.

The message footer follows suit: instead of one opaque total, each assistant reply shows its input/output split. Input-heavy turns (big context, long history) look different from output-heavy ones (long generations) — and that difference is exactly what you tune with presets, compaction, and retrieval budgets.

Both lines are quiet, muted-text adornments. They appear whenever the metrics exist and stay out of the way when they don't. You can see both live in the thumbs-up video in the previous section — the receipt under the search card, the split in the actions row.

Saved transcriptions, now deletable

Remove the entry, keep the transcript — or cascade the delete into the knowledge base. Your call, per delete.

Saved rows on the Transcriptions page finally have a delete. A trash icon on every saved row opens a confirm dialog with one clear choice: remove just the entry from this page, or also tick a checkbox to delete the saved transcript from the knowledge base. The checkbox only appears when a linked knowledge item actually exists — and it starts unchecked, so the safe option is the default.

The cascade is ordered to be safe, too: the knowledge item goes first, and if that fails the dialog stays open with an error so you can retry — or fall back to deleting just the entry. On success, a toast confirms it and the row leaves the Saved group.

It's deliberately row-level only — no bulk delete, no delete buried inside the review sheet. Data deletion should be a considered, one-at-a-time action, and the UI treats it that way.
