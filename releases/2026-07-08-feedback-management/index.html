Feedback triage

Every thumbs-down, in one place.

The /feedback console is the admin review surface for everything users rated about agent responses. It leads with a quiet one-line verdict in the page header — "{percent}% positive · {negative} negative" — and a full data table of ratings: a thumbs chip per row (ThumbsUp on success/10 for positive, ThumbsDown on destructive/10 for negative), the feedback preview, agent, user, and a relative date.

The toolbar slices thousands of ratings down to the one that matters. A single click on the Negative segment of the Type control (All · Negative · Positive) narrows the list to just the thumbs-down rows — the same score: { eq: 0 } filter the summary's negative link-button applies. Alongside it: a debounced "Search feedback…" box (300ms) and two async "Filter by agent" / "Filter by user" comboboxes, all composing into one server-side query. Any active filter reveals a Reset, and changing any filter resets to page 1.

GraphQL — the Negative tab is just a filter on one query — pull it from the API the same way:
query GetFeedback($page: Int!, $limit: Int!, $filters: [FilterFeedback]) {
  feedbackPagination(page: $page, limit: $limit, filters: $filters) {
    pageInfo { itemCount pageCount }
    items { id score description agent user createdAt }
  }
}
# filters: [{ score: { eq: 0 } }]   ← the Negative tab

Feedback detail & replay

See the whole conversation behind the rating.

Click any feedback row and a detail Sheet slides in from the right, reconstructing the whole interaction behind the rating. The header carries a round type chip and the "Negative feedback" / "Positive feedback" label with a RelativeTime; a two-column meta grid lists User, Agent, and Session — each next to a copy-id button — and an Open in Chat button links straight to /chat/{agent}/{session} to continue or correct the thread.

The payoff is the Conversation section: the full session transcript rendered by the real chat MessageRenderer — the same component the live chat uses — mounted read-only. User messages sit right-aligned in a bg-secondary bubble; assistant replies render left-aligned as plain body text. Tool calls, reasoning blocks, citations, and todo lists all render exactly as they did in the session; you just can't edit or regenerate. Above it, the author's Feedback comment sits in its own muted block.

GraphQL — the replay is one query — pull the session transcript, render it in the real chat UI:
query GetAgentSessionMessages(
  $page: Int!
  $limit: Int!
  $filters: [FilterAgent_message]
) {
  agent_messagesPagination(page: $page, limit: $limit, filters: $filters) {
    items {
      id
      session
      content
      createdAt
    }
  }
}

The health of every answer, in one line

A percent-positive / negative-count split that reads the whole corpus, not just the page.

The console leads with a quiet one-line verdict in the page header — "{percent}% positive · {negative} negative" — that reads the whole corpus, not just the page you're on. The two counts come from a pair of count-only GET_FEEDBACK probes (limit: 1, reading pageInfo.itemCount for score: 1 and score: 0) that poll every 30 seconds, so the split stays current as new thumbs land, and the header simply renders nothing until there is at least one rating to summarise.

The negative number is itself a link-button: clicking it drops you straight into the negatives (onSelectType("negative")), because a review console should make the thing you actually need to fix one click away. The whole list runs cache-and-network with a 30s poll, so the page is live without a manual refresh.

Names, not ids — and delete fifty at once

The list hydrates raw ids into real names, then lets reviewers clear ratings in bulk.

The list solves the "raw id" problem the backend still hands it: for each visible page it batches one GET_AGENTS_BY_IDS and one GET_USERS_BY_IDS call and maps every author and agent id to a real name — users composed from name, then firstname/lastname, then email, then id — with the raw id kept only as an honest last-resort fallback. The layout is responsive by breakpoint: a full data table at md+ (Type · Feedback · Agent · User · Date with a select column) collapses below md into a tap-friendly card list, each card a ≥44 px hit target with a thumbs icon, two-line preview, and relative time.

Reviewers can multi-select across the page and clear ratings in bulk: the selection bar's "Delete {count}" opens a confirm dialog — "Delete {count} feedback items?" / "This permanently removes {count} feedback records. The chat sessions themselves are not affected. This cannot be undone." — before firing one delete per row and toasting "Deleted {count} feedback items". Checkbox clicks stop propagation, so toggling selection never opens the detail panel.

GraphQL — the console's only write op — every bulk and single delete funnels through it:
mutation DeleteFeedback($id: ID!) {
  feedbackRemoveOneById(id: $id) {
    id
  }
}

An admin surface that fails closed

The gate is enforced on the server, not hidden in the client.

/feedback is an admin review console, and the gate is enforced on the server, not hidden in the client: a server layout.tsx wraps the client page in guardRoute("feedback"), so an account without the right is served the shared <AccessDenied/> primitive server-side rather than a flash of guarded content. The requirement is declared once in nav-config.ts and reused by both the sidebar and the guard, honouring the "nav-hidden must imply route-guarded" rule.

Today that requirement is super_admin, with a TODO in the config to flip to a dedicated feedback role key when the backend role-model ships. Denial is transparent by design: AccessDenied names the missing right instead of silently bouncing anyone. This console is the review end of a loop that already starts in chat — the 👍/👎 trajectory feedback shipped in chat-quality-of-life and the thumbs-down that deactivates the offending source (chat-trust-and-control) are where ratings are created; /feedback is simply where an admin triages what those interactions produced.
