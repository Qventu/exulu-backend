Theme studio

Your platform, your brand — previewed live.

The super-admin Theme page is a two-pane studio for white-labeling the whole product — "White-label IMP for your organization — changes apply to every user." On the left, every CSS design token from the manifest is grouped under quiet headings — Surfaces, Text, Brand, Semantic, Charts, Sidebar, Shape & typography — behind Light and Dark tabs with per-mode modified-count badges. A "Filter variables…" search and a "Modified only" switch keep the list tight; each row carries a color swatch, its mono token name, an inline value input, and a per-token reset.

On the right, a sticky preview card samples the real UI — buttons, a card with badges, an input, a mini chat exchange, a 10-color chart ramp — and re-renders on every keystroke, with its own sun/moon toggle that never touches the admin's own app theme. Edit the --primary hue and the primary button, the Active badge and the user chat bubble sweep through color live, while everything reading a different token stays exactly where it was.

Publishing is a decision you can see. The confirm dialog "Publish this theme?" reports "{lightCount} light / {darkCount} dark overrides — this applies to every user." — the same counts as the tab badges, so what you confirm is what you just saw. On success, "Theme published — It's live for you now — other users get it the next time they load the app.": the publish swaps a runtime style tag with no reload for the publishing admin. Color tokens that don't parse get an advisory note — "Not a recognized color value — it will be published exactly as typed." — a guardrail, never a gate. And "Reset to defaults…" is a real destructive confirm: "Removes all overrides ({count}) and immediately publishes the stock theme to every user."

Role matrix

Least-privilege roles in seconds.

The role editor is now a single narrow panel with a real permission matrix. Seven rows — Agents, Routines, Variables, Users, API, Evals, Budgets — each carry an icon, a label, an info tooltip, and a three-state None / Read / Write segmented control. The whole access model of a role fits one viewport: the redesign collapsed ~1400px of stacked permission cards into ~320px, inside a 448px side panel, with no nested cards and no scrolling between areas.

Every change is instantly legible. Flip a segment and a sticky Save bar slides up from the panel bottom — "You have unsaved changes." with an outline Discard and a primary Save — the primitive renders nothing at all until the draft is dirty. A shield-marked line under the matrix states the blast radius plainly: "Members of this role see navigation changes immediately." Each row's tooltip carries the area's scope verbatim, from Agents' "AI agents and their configurations." to Budgets' "Spend budgets for users, roles, teams, projects, and agents."

The reserved roles are protected end to end. admin and default get a "System" badge, a locked name field ("System roles cannot be renamed.") and a disabled delete ("System roles cannot be deleted."). Deleting any other role keeps member accounts but revokes its grants ("Members of this role keep their accounts but lose its grants. This cannot be undone."). And legacy permission strings still render correctly: the matrix normalizes any stored value by keyword — write/create/update/delete become Write, read/view become Read — so old roles show up faithfully in the new control.

Permissions are plain role fields — grant them via GraphQL:
mutation UpdateUserRole($id: ID!, $budget_management: String) {
  rolesUpdateOneById(
    id: $id
    input: { budget_management: $budget_management }
  ) {
    item {
      id
      name
      budget_management
    }
  }
}

Theme CSS import & export

Paste a stylesheet, ship a brand.

The Theme studio's overflow menu round-trips whole themes as CSS. Paste any stylesheet with :root and .dark blocks into "Import theme CSS" and the dialog parses it live, before you commit: a running count reads "{lightCount} light · {darkCount} dark variables detected", unreadable declarations are listed under a non-blocking warning ("N lines couldn't be read and will be skipped:"), and a missing-block paste gets the honest hint "No :root or .dark block found — paste a complete CSS theme." The dialog is explicit that nothing ships yet — "Paste a full CSS theme with :root and .dark blocks. Detected variables merge into your draft — nothing changes for users until you publish."

Variables the manifest doesn't recognize don't get dropped — they land in a trailing, fully editable "Custom" group, and the editor flips to "Modified only" so you see exactly what arrived. Going the other way, "Export CSS" puts the published theme on the clipboard ("CSS copied to clipboard"), and "Show raw configuration" reveals the stored overrides as copyable JSON ("Stored configuration (JSON)") next to the generated stylesheet ("Generated CSS (published theme)") — deliberately the live theme, never the unpublished draft. The parser reads the first :root and .dark blocks, so import expects a flat theme file, not arbitrary nested CSS.

Variables vault

Secrets that stay in the vault.

The rebuilt /variables vault treats every value as sensitive by default — "Secrets and environment variables your models, agents, and integrations depend on." New variables are created as "Secret — encrypted at rest" unless you explicitly pick "Plain text — stored as-is", and the list page never receives values at all: the list query selects only name, type, and timestamps, while a reveal in the detail panel fetches the value on demand under a no-cache policy, so the secret never lands in the client cache.

Revealed values re-mask themselves after 30 seconds ("Value revealed for 30 seconds."), copying works without revealing, and edits that can break things downstream go through a change-impact confirmation first: "Renaming \"{oldName}\" to \"{newName}\" will break any agent or model that references the old name." and "Switching from Secret to Plain stores the value without encryption — consumers that decrypt it may break." Consumer usage tracking isn't wired to the backend yet, and the UI is honest about it rather than faking a count — the "Used by" column reads "Usage unavailable" and the detail panel degrades to "Usage tracking is not yet available from the backend."

API keys cockpit

Credentials with a paper trail.

The scoped keys announced yesterday now have a proper cockpit. The /keys page is a live audit surface: the table polls every 30 seconds, so "Last used" is current — and a credential that has never authenticated wears a "Never" badge, which the code itself calls an audit signal. Creating a key is a two-step wizard in one dialog: step one names the key and picks a scope from two option cards — "Admin" ("Full access. Currently acts as a super admin, regardless of the selected role.") with a role selector, or "Agents" ("Read-only access to the agents on the allowlist.") which replaces the role field with an agent-allowlist builder.

Step two reveals the key exactly once, with Esc, outside-click, and the close button all disabled until you press Done: "This key is shown only once — copy it now and store it securely. You won't be able to view it again." The plaintext is generated in the browser and hashed before it's stored, so the hash never travels to the list. Click any row and the detail panel opens with the log-matchable mask (sk_…/production — "The suffix after "sk_…/" identifies this key in logs."), role reassignment behind its own confirmation ("Change role?"), and revocation in a Danger zone: "Requests using this key stop working immediately." Optional team and project selectors attribute requests for cost tracking.

Admin-scope keys don't restrict by role yet, and the UI says so verbatim — "Admin keys currently act as a super admin — the selected role does not restrict them yet."

Personal token

Your bearer token, five seconds flat.

The /token page is a single card built for one job: grab a working bearer token fast, without ever burning it onto the screen. Titled "Personal token" — "Your bearer token for the IMP API." — the token sits in a masked field where copy works without revealing, under the plain security note "This token acts as you. Keep it private." An expiry chip decodes the JWT's exp claim into an honest status: quiet green while more than an hour remains ("Expires in {hours} h"), orange under an hour ("Expires in {minutes} min"), red once dead ("Expired — sign in again"). The chip is static by design — a ticking countdown is anxiety, not transparency.

A collapsed "Usage example (cURL)" disclosure carries a copyable request with your deployment's backend URL pre-filled — and the token stays a placeholder in the snippet, because the page never renders the secret in plain text.

From the /token page — cURL
curl -X POST $EXULU_BACKEND/graphql \
  -H "Authorization: Bearer $EXULU_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"{ agentsPagination(page: 1, limit: 10) { items { id name } } }"}'

GraphQL explorer

The whole API, signed in as you.

The /explorer admin surface embeds a full GraphiQL workbench against your deployment's /graphql endpoint — schema docs, autocomplete, query history, the works. Your session token is injected automatically from the live session, so every query you run executes with your real permissions: what you can read here is exactly what your integrations can read with the same credentials, making it the honest sandbox for API work before you mint a key.

n8n embed

Automation, embedded (honestly).

The Automation page embeds the full n8n editor in an iframe sized to the remaining viewport — clipboard access allowed, a skeleton overlay until the canvas loads, and a ghost "Open in new tab" escape hatch — whenever N8N_URL is configured on the server ("Build and run automations in the embedded n8n editor."). Below desktop widths the page refuses to ship a cramped 390-px canvas and says so instead: "The n8n editor needs a larger screen", with "Open the editor in a new tab on desktop to build and debug automations." and the same open-in-new-tab action as the way out.

When N8N_URL is unset the route denies access, and the defensive empty state reads "Automation is not configured" / "Set N8N_URL on the server to enable the embedded editor."
